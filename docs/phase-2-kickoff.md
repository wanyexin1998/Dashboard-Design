## 三、已知限制与技术债

细节见规格 §9「建议（未实施）」。

1. **数据是固定示例**：`DATA`（指标）与 `FACT`（筛选 / 表格）是写死的事实，15 个图表的数据是模块内常量。截至日只能在 9/1–9/22 之间移动，只有筛选 / 页签 / 表格与 K04、K05 跟随。
2. **无障碍缺口**：原 15 个图表和指标组件的切换 / 选中不播报；B05 / B06 是手写表，没有 ↑ ↓ 行导航，成员行 / 子行键盘到不了。
3. **待定的不一致**：矩阵切换季度时保留选中，与页面「切换时间范围后清除旧选择」的说法相反；截至日胶囊写「全页截至」，范围说大了；组合图图例没有标左右轴。
4. **还不是组件库**：所有组件都在一个页面里，通过 `ChartDemos` 登记，共用全局的 `ChartKit` 和 `ChartInspector`；没有按需引入、打包和类型。
5. **测试是脚本**：Playwright 脚本靠固定等待时间，换到更慢的环境（比如 CI）可能要放宽等待。
6. **可清理的代码**：已隐藏的旧提示框、没人用的 `KpiKit.canvas()`、被覆盖的高度声明等。

## 六、开工步骤（不论选哪个方向）

1. `git pull` → `npm install` → `npx playwright install chromium` → `npm test`，确认基线全绿。
2. 每项工作开一个分支：改 `src/` → `npm run build` → `npm test` → 同步规格 → 源码和产物一起提交。
3. 新组件或大改动先写方案稿（放在 `docs/proposals/`），拍板后再实现，决策记进规格 §9「已决」。
